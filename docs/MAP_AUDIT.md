## 1. What was wrong, and what changed

### Temporal model (shared layer: `src/atlas/gazetteer.ts`)

| Problem | Effect | Fix |
|---|---|---|
| `matchName` returned `unique` for the only place of a name whatever its dates; confidence was decided ad hoc in `resolve.ts`, and **`offlineUnique` (the reader's underlined place names) ignored dates entirely** | A place first recorded in 1300 was underlined as a known place in a book set in 1100 | Identity and temporal support are now separate fields (`status`, `temporal`) combined once in `placeConfidence` → `certain / probable / possible / ambiguous / unresolved`. `resolve.ts` only maps it (`CONFIDENCE_OF`); the reader underlines only certain/probable places |
| An undated record that was the only match was "likely" (MEDIUM) | Missing evidence read as evidence | `possible`, or `probable` when the book's own places are nearby |
| A place picked only because its namesakes are first recorded later was HIGH | "Not recorded yet" treated as "did not exist" for the rivals | `probable`, with "the others may still have existed then" in the reason |
| Dates within the 50-year slack counted as "recorded at this date" | A first mention in 1140 made a place certain for 1100 | New `approximate` support → `probable` |
| Records of one place from several datasets: the shown record was chosen by date fit only | An incidental out-of-region record (the Lübeck case) or Wikidata could stand in for the specialist record | Record inside its dataset's documented region first, then specialist before aggregator (Wikidata); the place's **dates come from the best-supported record of the group**, so no evidence is lost |
| Wording for a record without dates whose evidence period starts after the year: "records only its end (undefined CE)" | Wrong explanation | Correct wording |
| Place cards said "Pleiades periods, not founding dates" under **every** record's dates | Mislabelled EBIDAT, DicoTopo, Viabundus… dates | Each record states its own basis (`dateBasisNote`), plus "At <year>: First recorded later; may have existed earlier" etc. (`TEMPORAL_LABEL`) |
| EBIDAT castles: end of use went into the tiles but not the gazetteer | Map and gazetteer disagreed after a castle's end | End date now in both |
| English/Welsh market grants (2,371 records) had no date in the gazetteer | Markets undated in lookups although the map had the grant year | First grant = first attestation |

The shared scale, in one place (`placeConfidence`):
- **certain** — identity settled (the only place of the name, or the book's geography picks it with no rival attested at the date) *and* its dates cover the year (or an evidence period does and the book agrees);
- **probable** — recorded only close to the date or only earlier (places persist), an evidence period only, picked because namesakes are first recorded later, undated but in the book's area;
- **possible** — first recorded only after the date, or no temporal evidence;
- **ambiguous** — several places fit; **unresolved** — none of that name, or every one began after the date.

### Data and build (`scripts/atlas-build/quality.py`, used by `tiler.py` and `world.py`)

| Problem found by the audit | Fix |
|---|---|
| **Itiner-e: an unknown date is stored as 0 in the shapefile; the build copied it. ~14,800 of ~16,400 Roman road segments were therefore "dated" to year 0 (which does not exist) and never drawn at any date.** | 0 is read as "no date" (Itiner-e step, and generically: a year 0 removes only that field). Undated segments now show, faded, inside the dataset's period |
| Coordinate validation (the EBIDAT longitude 36578 fix) applied only to the private-pack path | Every gazetteer row and tile feature goes through `position_problem` (range, NaN, 0/0) |
| Impossible dates (end before start: 3 Germania Sacra, 1 DARMC; year 0: Princes & Townspeople, 1 Wikidata) | Dates removed with a stated note; the record kept. For Princes & Townspeople a 0 is skipped *before* the earliest evidence is chosen, so the charter date becomes the start |
| Duplicate source ids (Germania Sacra 320 — one institution, several seats; Danish register 2,821 — several finds per locality): the id index reached only the last one | All kept; later ones get a unique key (`4068~2`) with the source id kept (`sid`, used for the record link); a map click resolves to the record at the clicked spot |
| Tile encoder wrote invalid polygons (snapping to the 4096 grid pinches narrow necks) | `on_invalid_geometry_make_valid` + repair of invalid simplified/source polygons, same dimension kept |
| False precision: positions with under 2 decimals, and 3+ records of one dataset at one exact point (a commune or locality point), were marked "Location known" | Marked approximate with the reason (`pq`) |
| TIB: 7 records are present-day libraries and museums (where manuscripts are kept), not places; TIB area centroids were marked exact | Repositories excluded; centroids approximate |
| Documented dataset regions too narrow (Germania Sacra's Prussian/Livonian houses, EBIDAT's Finnish castles, Pleiades' Africa/India, a Red Sea wreck) | Boxes widened to the data; the audit lists records outside them |

### Private data

| Problem | Fix |
|---|---|
| **The Atlas of Rural Settlement shapefile (private: "no republishing") was committed to the public repository** (`data/historical/raw/atlas-rural-settlement/original/atlas-gis-shapefile.zip`, since commit 89eb599): `sources.json` did not mark it local-only although the app, the Vite plugin and the pack builder all treat it as private | Marked local-only, `.gitignore` regenerated, file removed from the index (kept on disk). **It is still in git history**; removing it from history needs a force-push of `main` — your decision. ### Server (`server/static.ts`)

The static file server checked containment with `file.startsWith(DIST)`: `/..%2fdist-private/…` resolved to a sibling folder
whose name starts with "dist" and passed. Now: path-relative containment on real paths (symlinks resolved), undecodable
paths and NUL bytes refused. `server/static.test.ts` covers `..`, encoded separators, backslashes, the sibling prefix, a
symlink out and malformed encoding. (The server listens on 127.0.0.1 by default; GitHub Pages does not use it.)

## 3. Verified and left as they were

- `time.ts` already separates `within / near / period / earlier / later (founded) / unattested (first recorded later) /
  undated`, end-only records (`unattested` before the end), and envelope records; the map's site layers already hide
  end-only records before their end and draw not-yet-recorded ones hollow only on request.
- Wikidata: "inception" counts as a founding date only for castles, religious houses, cathedrals, bridges and
  universities; for settlements it is "recorded start (Wikidata inception)" (10,933 records), i.e. evidence, not founding.
- Naming (`names.ts`): the book's wording if recorded → a recorded English name → a Latin-script title or name
  (published romanization schemes only; Arabic, Hebrew and Armenian are never guessed) → the original script. Nothing is
  discarded for lack of an English name.
- The paint-follows-the-year fix is general (all managed layers re-apply paint on year change).
- The historical proxy (`server/historical.ts`) validates ids and talks to one fixed host.
- The private pack stays out of git and out of builds: `.gitignore`, the Vite `keepLocalDataLocal` plugin, and tests
  on git's tracked files and on `dist/`.

## 4. Remaining limitations (not solved here)

- The rural-settlement ZIP remains in git history (see above).
- Records flagged for review in `DATA_QUALITY.md` (offshore points, coarse positions, shared positions) are listed,
  not changed, unless a rule above applies.
- A dataset's documented region is a box, not a polygon; "outside the region" is approximate.
- `earlier` (recorded only before the year) is shown as "probable — places persist" for every dataset; an EBIDAT end of
  use or a destruction date is the same kind of field, so a castle after its end is shown as probable, not as gone.
- Coverage gaps that are **data gaps**, not software faults: Hungarian villages and churches (Engel's atlas is locked
  in an encrypted program), Bulgaria, Byzantine Anatolia, Ukraine/Belarus, Italian and Iberian medieval roads and
  polities, rivers and forests before 1500. See the coverage table in `DATA_QUALITY.md`.
- Four vault datasets are acquired but not integrated (raw only): CShapes (1886–2019), Historic England, Living with
  Machines, Beyond the Tribal Hidage.
- Mobile: the pack install was verified in a phone-sized Chromium, and earlier on the owner's S21; low-memory phones
  are untested.

## 5. Follow-up: undated records on ancient maps (1 October 2026)

**Problem.** With "Include undated records" on, a map of 68 CE drew 1,958 medieval sites in Poland, 19,318 in Germany,
33,473 in France and 4,888 in Italy. Two kinds: records with no date at all (mostly Wikidata castles, religious houses,
cathedrals and dioceses, which the snapshot takes regardless of date), and records first recorded later (a church first
mentioned in 1200, a DicoTopo commune first attested in 1150), which were drawn hollow at every earlier year back to
3000 BCE.

**Hidden temporal evidence, audited per dataset** (nothing invented; what is not in the source stays missing):

| Dataset | Undated records | What the source holds | Used? |
|---|---|---|---|
| Wikidata snapshot | 39,880 items without inception, first mention, dissolution or start/end | Other dated statements, fetched for those items only (`wikidata_dates.py` → `raw/wikidata-medieval/original/temporal-evidence.json`): 4,087 statements on 3,136 items — architectural style 2,806, P31 start 576, dated events 377, opening 172, time period 106, culture 50 | **Yes**: 826 records get a first attestation (earliest dated event/opening/use — evidence it existed then, never a founding); 1,094 get an evidence period from their style, time period or culture, using only the dates Wikidata records for that style/period (styles with no recorded dates add nothing) |
| Wikidata descriptions | — | A century or year in about 3 % of descriptions, often of a later rebuilding | No — too ambiguous |
| EBIDAT | 1,112 ("unbekannt" 1,096, "Älter" 16); end dates already imported | 72 history texts say "erstmals erwähnt <year>", but often of the village, a church or a successor | No — would date the wrong thing |
| TIB | 693 with geometry (mostly rivers, regions, islands) | No dated relations; scholarly prose covering many periods | No |
| Markets and fairs (private) | The map tiles lacked the grant year the gazetteer already had | First grant per place | **Yes**: not drawn before its first grant |
| DicoTopo, Germania Sacra, Nordic, Bridges | Dated by first attestation | — | Already imported; only the display before the first record changed |

**The map rule (revised the same day, at the owner's choice — the problem was at every date, not one):**
- Records with dates or an evidence period: unchanged.
- First recorded later, or before an evidence period begins: drawn hollow from **60 years** before that record, never
  further back (only when "Include undated records" is on).
- No date at all (or only an end, which says nothing about a beginning): never on the overview map. With "Include
  undated records" on, they appear as **grey "?" dots from zoom 9 (town level)**, inside their dataset's period.
- Measured, Poland area, undated records on, overview zoom: 900 — 2,988 → 396; 1100 — 2,675 → 531; 1200 — 2,800 → 869
  (without undated records: 387, 482, 714). At town zoom the undated places are all still there (1,750–2,970).

The first version of the rule, kept for the record (`sitePoints`, `catalog.ts`; windows written by `with_window` in `sites.py`):
- Records with dates or an evidence period: unchanged.
- A record with no evidence at the chosen year — no dates, first recorded later, only an end date, or before its evidence
  period begins — is drawn only when the reader includes undated records, and then only inside the period its dataset
  documents itself as covering (the `core` of the dataset registry, e.g. Wikidata 500–1650, DicoTopo 800–1600), as hollow.
  That window is a display bound, not a date for the record: in lookups the record stays "no dates in the source".
- A building style dates the building's form, not the place's beginning, so a church listed as Baroque (from 1600) is
  still shown (hollow, on request) in 1300.
- Tiles built before this change fall back to the site layers' own period (300–1900).

**Measured** (site layers, all records drawn, "Include undated records" on, 68 CE): Poland 1,958 → 6, Germany
19,318 → 15, France 33,473 → 31, Italy 4,888 → 88 (those left have dates at or before 68 CE: early fortifications,
dated shipwrecks). At 1200 CE with undated records on, more is available than before (Poland 2,615 → 2,800); nothing
was removed. Default views (undated off) are unchanged.
